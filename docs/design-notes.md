# PomoSingle 設計ノート

なぜそう作ったか、の記録。使い方は [README](../README.md) に、ここには判断の理由と、同じ失敗を繰り返さないための技術上の注意を残す。機能を足すときはここに理由を書き足す。

順序は README の並びに合わせてある: 画面 (Focus View / 休憩 / 管理画面) → 一覧の部品 → 仕組み。

## 3 つの画面

| モード | いつ | 見えるもの |
| --- | --- | --- |
| **Quick Capture** | いつでも(ホットキー / 画面のボタン / Focus View のダブルクリック) | 入力欄だけ |
| **Focus View** | ポモドーロ実行中 / 短い集中 | タイマー + 着手中タスク 1 件のみ |
| **Manage View** | ポモドーロ外 | 一覧・一時メモの整理・サブタスク |

- Quick Capture は既定で `Ctrl+Alt+Space`。どのアプリの上からでも呼べて、Enter で一時メモに落ちて即座に消え、直前のアプリにフォーカスが戻る。
- そのキーが他のアプリに取られている場合は `Ctrl+Shift+Space` → `Ctrl+Alt+N` → `Ctrl+Shift+N` → `Ctrl+Alt+Q` の順に空きを探し、採用したキーを設定に書き戻して通知する。Quick Capture が使えないと運用自体が成立しないため、登録失敗で放置しない。
- Focus View は一時メモの**件数を既定で表示しない**。「入った」ことだけを小さなパルスで伝える。残件数が見えること自体が割り込みになるため。
- 休憩フェーズに入ると Focus View が自動で triage 表示になり、溜まった一時メモを 1 件ずつ「タスクへ / 後で / 削除」に振り分けられる。本文が長いときは本文だけがスクロールし、ボタンは常に見える位置に残る。
- **さっきまでのタスクに区切りを付けられる** (完了にする / 待ちにする)。休んでいるうちに「あれはもう終わっていた」「返事待ちだった」と気づくことがあり、次の集中まで持ち越させない。ただし**名前は見せない** — 休憩中にタスク名が目に入ると休めない。見出しの右端の札を押したときだけ開き、休憩の最初から押せる (気づくのは休憩に入った直後が多い)。片付けた後は札が緑になる。休憩中なので 3 択には入らず、状態を変えるだけ。
- **休憩中の進捗バーは減っていく。**集中中は積み上げた分を伸ばすが、休みは積み上げるものではなく使い切るもの。同じ向きに伸ばすと、休憩が終わりに近づくほどバーが満ちて達成感のような読み違えを招く。
- **休憩中は画面全体に暗幕をかける** (設定で切れる)。休憩に入れないまま次の 1 本を始めてしまう人向けの強制力。全モニタを 1 枚で覆い、3 秒かけて落とす。**クリックは素通しする**ので手は縛らない — 会社の PC で急ぎの連絡が来たときに逃げ場が無いのは困る。代わりに「続けるなら画面が暗いまま」という居心地の悪さだけを残し、休むのが既定で続けるのは押し切る行為、という向きに反転させる。Focus View は暗幕の上に出したままにする (残り時間と振り分けが見えないと意味が無い)。
  - 濃さは設定から選ぶ (薄め / ふつう / 濃め / ほぼ真っ暗)。画面の明るさも、周りから覗かれる席かどうかも人によって違う。
  - **Focus View のボタンでその場で外せる。**PC で休む (動画を見る、調べ物をする) のも休憩で、そこを暗幕で潰すと休憩自体を避けるようになる。外したことは**今の休憩の間だけ**覚え、次の休憩ではまた掛かる。
  - 掛けるときは毎回 0 から 3 秒かけて落とす。目的は驚かせることではなく「そろそろ手を止める時間だ」と身体で分からせることなので、いきなり暗くしない。窓は休憩ごとに作り直さず hide/show で使い回すため、掛け始めは CSS アニメーションではなく Rust 側から関数で叩いている (アニメーションのままだと最初の 1 回しか走らない)。
  - **引くときもフェードするが、0.8 秒と短い。**一気に明るくすると画面が弾けたように見えるが、掛けるときと同じ 3 秒では、もう手を動かしているのに暗いまま待たされる。掛けるのは合図、引くのは後始末。窓を隠すのはフェードが終わってから — 即座に隠すと、明ける前に消えてしまう。待っている間に掛け直されることがあるので、隠す直前にもう一度確かめている。
- **休憩中も下段の計測器は集中中と同じ。**時計は同じ場所・同じ大きさで、振り分けは集中中にタスク名が座っていた領域に出す。休憩はむしろ「あと何分休めるか」が主題なので、時計を小さくする理由がない。切り上げは計測器の ⏭ に移した。

## 短い集中 (助走)

25 分が重くて着手できないときのための、**ポモドーロではない**短い枠 (既定 10 分)。開始ボタンの左の控えめなボタン、またはトレイから始める。

- **実績には一切数えない。**🍅 も付かず、今日のポモドーロ数にも入らず、長い休憩の周期にも数えない。日次の集計はセッションの種別が `focus` のものだけを見るので、`short_focus` は自動的に外れる。
- 守っているのは **1 🍅 = 標準の集中 1 本**という単位。タスクの 🍅 と今日のポモドーロ数は「自分の 25 分でどれくらい進むか」を育てるための唯一のフィードバックで、1 🍅 が「10 分か 25 分のどちらか」になった時点でその回路は死ぬ。
- Focus View のフェーズ名は「集中」ではなく**「短い集中」**。今がポモドーロでないことが常に分かるようにする。
- **後に休憩を挟まない。**10 分の助走に 5 分の休憩を足すと、温まった勢いをそこで切ることになる。終わったら一覧に戻り、「同じタスクでもう一度」でそのまま本番の 1 本に入れる。
- 手が空いたとき (完了・待ち) も**残り時間の使い道は聞かない**。守るべき 25 分の枠が無いので、そこで区切って一覧に戻す。
- 次の予定の判定も短い枠の長さで別に見る。標準の 1 本が入らなくても、短い方なら入ることがある。

**なぜ「長さを自由に変える」ではないのか。** 原典では、ポモドーロは**測る単位**である。長さを変えること自体は禁じられていない (25 分も実験の結果) が、禁じられているのは**タスクに合わせて変えること**で、長さは自分の設定であってタスクの性質ではない。可変長にすると「このタスクは 3 ポモドーロ」という見積りも、「5〜7 本を超えるなら分割」「1 本に満たない用事はまとめる」という派生ルールも同時に壊れる。だから標準の長さは 1 つに保ち、助走は**別の道具**として、実績とは別の帳簿に置いた。

## 休憩が終わったら管理画面に戻る

**仕様。**休憩のあとは自動で次の集中に入らない。次の 1 本を始めるかどうか、始めるならどのタスクかは、毎回自分で決める。着手中のタスクが終わっていなくても同じで、続きをやるなら管理画面でもう一度そのタスクを選んで始める。

そのために、集中と休憩の間は一覧を視界から外し (Focus View だけ表示)、Idle に戻ったところで一覧を出す、という切り替えにしてある。休憩明けに黙って次の 25 分が走り出すと、「今からこれをやる」と決める場が無くなり、惰性で同じ仕事を続けてしまう。

ただし、続きをやるのが明らかなときまで選び直させる必要はない。休憩明けに着手中のタスクが残っていれば、開始ボタンが**「同じタスクでもう一度」**に変わる。押せばそのタスクで次の 1 本が始まる。自動では始めないが、選び直す手間は無い。持ち越すのは真偽値ではなく**タスクの ID** — 休憩明けに別のタスクを選び直したときに「同じタスクで」と名乗ったら嘘になる。

## 全画面

補助モニタを使っていると、そちら側の視界情報 (チャットの通知、開いたままのブラウザ) が集中を削る。Focus View を**モニタ 1 枚いっぱいに広げて**、その画面ごと覆い隠せる。

- Focus View の右下のボタン、または設定から。**広げる先は、そのとき Focus View が載っているモニタ**。補助モニタに出したければ、小窓を一度そちらへ動かしてから押す。
- 押したモニタは覚えるので、次のセッションからは同じモニタに出る。小窓に戻すときも、そのモニタの右下に戻る。作業用モニタの隅に戻ってくると、探すことになる。
- **中身と並びは小窓とまったく同じ。**寸法だけを画面に合わせる。並びまで変えると、小窓と全画面で別のアプリになってしまう。タスク名が中央、計測器は下段のまま。
- 内訳・メモ・待ちの入力は、**タスク名のすぐ下に、左端を揃えて**開く。幅は 780px で切る — ウルトラワイドで 1 行が端まで伸びると目で追えない。中央に置くとタスク名と別物に見えるので、左端を揃えている。
- 全画面のあいだは**最前面を強制**し、**半透明の設定にかかわらず不透過**にする。覆い隠すのが目的なので、透けていては意味がない。
- 最大化 (`maximize`) は使わず、モニタの矩形に合わせて `set_size` している。最大化した窓には `set_size` が効かなくなり、小窓に戻せなくなるため。タスクバーごと覆いたいので、作業領域ではなくモニタの矩形そのものに合わせる。

高さの決め方が小窓と逆 (中身に合わせる ⇄ モニタに合わせる) なので、全画面のあいだはフロント側の測り直しも Rust 側の `resize_focus` も止めている。

## 鳴る前に手が空いたら

タイマーは止めない。ポモドーロは分割できないという原則を保つため。完了をチェックする、または**待ちに回す**と、Focus View が残り時間の使い道だけを聞き、残り時間の長さで推奨が変わる。

| 選択肢 | 何が起きるか | 推奨されるとき |
| --- | --- | --- |
| 見直す | 同じタスクのまま「見直し」表示で鳴るまで走る | 残り 4〜9 分 |
| 次をやる | 候補 3 件から選び、**同じセッションを引き継いで**次の 1 件へ | 残り 10 分以上 |
| 休憩へ | セッションを終えて休憩に入る | 残り 3 分以下 |

候補の並び順は、手を離したのがサブタスクなら**同じ親の未完了サブタスクを最優先**、次に**期限の近い順**、期限なしは最後。

**待ちに回したときは「見直す」を出さない。**相手の番になっている仕事を磨き直すことはできないので、選ばせても手が止まるだけ。残り時間が 10 分未満なら休憩を推す。

外せない不変条件が 2 つある。

- **完了は「中断」として記録しない。** 中断カウントは「何に集中を切られたか」を見る数字なので、約束を果たしたことで汚さない。
- **早めに休憩に入ってもポモドーロは 1 回として数える。** タスクを終わらせた人が実績で損をする設計は、必ず「終わっても報告しない」方向に歪む。

計上は「1 ブロック = 1 ポモドーロ」を保ち、タスク側の 🍅 はそのブロック中に着手した各タスクに 1 つずつ付ける(引き継ぎで二重計上しないようセッション単位で記録する)。

## Manage View の操作

| したいこと | 操作 |
| --- | --- |
| タスク / サブタスクを追加 | 見出しの右の「＋」、または**一覧の余白をダブルクリック**。「＋」なら先頭に、余白 (末尾の下) なら末尾に箱が出て、書いて Enter するとその場所に入る — 押した場所に現れるのが自然なため。箱は行と同じ骨組みで出るので左端が上の行のタスク名と揃う。欄外を押しても、書いてあれば追加する (空ならやめる)。常設の入力欄は置かない — 一覧の先頭に空の欄が居座らないぶん、1 行ぶん広く使える |
| 「次にやる 1 件」に指定 | **タスクをダブルクリック**、または「これをやる」ボタン |
| タスク名を変更 | **名前をクリック**してそのまま書き換え(Enter / フォーカス外しで確定、Escape で取り消し)。期限が無ければ、確定した流れでカレンダーが開く |
| 期限を設定 | **タスクを追加した直後、または期限の無いタスクの名前を変えた直後にカレンダーが開く。**入れなければ期限なし。あとから設定するときは行の「期限」ボタン。外すときは日付入力欄の枠の中にある「×」(カレンダーアイコンの右)。カレンダーを開いている間は、対象の行が枠で示される |
| メモを書く | 行の「メモ」ボタン。依頼のメール文や参照 URL の貼り付け用。離れると自動保存 |
| 一時メモに戻す | 行の「一時メモへ」ボタン |
| 並べ替え | 行の左の**グリップをドラッグ**。行の上下の端に落とすとその位置に挿入、**中央に落とすとその行のサブタスク**になる。一覧の末尾にも落とせる |
| サブタスクを親タスクに戻す | サブタスクを最上位の行の**端**に落とす |
| 待ちにする | 行の「待ち」ボタン。要因といつまで待つかを入れる。「待ち解除」で戻す |
| 削除 | 行の「削除」ボタン。**いったんゴミ箱へ入る**ので戻せる |
| 集中を開始 | 画面下端の「集中を開始」 |

期限は「次をやる」の候補の並び順に使われる。過ぎているものは赤、今日か明日は琥珀で表示する。

## 一時メモ

思いついたことと割り込みの置き場。タスクの注記 (メモ) とは別物なので、画面上は「一時メモ」と呼び分けている。DB 上は `status = 'inbox'`。

- 入り口は 4 つ。ホットキー、一時メモ欄の右上の「＋」、一時メモ欄の余白のダブルクリック、Focus View のタスク名をダブルクリック。管理画面の中の 2 つは別の窓を出さず、**一時メモ欄にその場で書ける箱**を出す (「＋」なら先頭、余白のダブルクリックなら末尾で、書いたものもその場所に入る)。視線を動かさずに済むし、欄外を押しても書いてあれば追加される (空ならやめる)。
- **出る位置は状況で変わる。**集中中は Focus View の左隣に下端を揃えて出す (左に入らなければ右隣)。画面が広いと、画面中央に出したのではタイマーから視線が飛びすぎるため。横に置くのは、行が増えたときに伸びてタイマーを覆わないようにするため。下端を揃えてあるので伸びる向きは上になる。集中していないときは画面中央やや上の定位置。
- **複数行を受ける。**依頼のメールやチャットを貼り付ける用途があるため、Enter で送信・Shift+Enter で改行。貼り付けた改行はそのまま残る。
- 「タスクへ」でタスクにするとき、**1 行目が名前・全文がメモ**になる。1 行だけの短いものは名前だけでメモは作らない。80 文字を超える 1 行は名前を切り詰めたうえで全文をメモに残す。
- 既にあるタスクのメモへ合流させる「タスクのメモへ」は以前あったが、使われず外した。一時メモは「後で判断する」ための箱で、判断は「タスクにする / 消す」の 2 つで足りる。
- 本文に URL が含まれていれば、一時メモの一覧からそのまま押せる。
- 逆向きに、タスクの「一時メモへ」で一時メモに戻せる。名前・メモ・サブタスクが 1 つの文章に畳まれる (構造は失われるが、書いてあった内容は落とさない)。

## タスクのメモ

各タスクに本文を持てる。依頼のメール文、情報の出どころの URL、調べたことの置き場。

- 一覧では本文を 1 行につないで (改行は空白 2 つに置き換えて — 1 つだと行の境目が詰まる) 手掛かりとして添え、幅に収まらない分は省く。全文は開いたときだけ出す。
- Focus View では**タスク名の右**に置く。メモも内訳のアイコンも「このタスクに付いているもの」で、タイマーや一時停止と同じ計測器の列に混ぜる筋合いがない。どちらも下端に寄せてある — 開いた中身はすぐ下に生えるので、押した場所と出てくる場所を近づけるため。完了と待ちも同じ理由でここに並べ、**完了 → 待ち → メモ → 内訳**の順 (左から「片付ける」順) にしてある。計測器の列に残すのは、タイマーそのものに関わるものだけ。
- **同じ操作には同じ絵。**Focus View と管理画面で使うアイコンは `src/lib/icons.tsx` に置いて共用する。画面ごとに描き分けると、「集中中に押したあのボタン」が一覧のどれなのか毎回文字を読み直すことになる。
- **行のボタンは行の上に重ねる。**押すまで見えないものにレイアウト上の席を確保し続けると、その分だけスクロールせずに見渡せる件数が減る。実測で **1 行 60px → 36px**、同じ高さに入る件数が **7.8 行 → 13 行**になった。
- **重ねたボタンは行の内寸に収める。**行より背が高いと、選択中の行では枠線を跨いで「行から飛び出した別の物」に見える。2 段のまま収めるため、行の中のボタンは上下の余白を行間で持たせ、パネルを `top: 2px; bottom: 2px` で行の内寸より一段内側に置いている。枠線に触れるほど詰めると、今度は枠線がボタンを貫いているように見える。
- **行の中のボタンは枠線を持たせない。**枠線があると、選択中の行のオレンジの枠とすぐ隣で線が二重になり、オレンジ同士が重なった箇所だけ濃くなって散らかる。代わりに地を塗って、線を 1 本も増やさずに「押せるもの」を示す。
- **手掛かり (期限・🍅・メモ) は名前のすぐ右。入るなら 1 段、入らなければ 2 段。**期限は名前から離すと意識に上らないので、右端に寄せない。右端をボタンの席として空けておくのも無駄なので、メモは残った幅を使って伸びる。1 段か 2 段かは**行ごとに実測して決める** — 名前の右に残る幅からボタンの幅を引いた値が「期限 + 🍅 + メモのアイコン」を賄えれば 1 段。メモの文字は数えない — ボタンを出している間はアイコンに縮んでよく、文字は入るなら出す程度でよい。ボタンの幅を最初から引いてあるので、ホバーの前後で段数が変わらず、行の高さが跳ねない。
- **名前の幅の上限も実測で決める。**ボタンの実際の幅 + 手掛かりの最小の形 (「まで」込みの日付か、🍅 とメモのアイコンの広い方) + 間隔。定数で見積もると必ずどこかに余りが出るので、ボタン・日付・🍅・メモの幅を測って行ごとに当てる。長い名前の行でホバーすると、日付のすぐ右にボタンが来る。
- **期限の「まで」は落とさない。**落とせば 22px 稼げるが、落としても余る行と落とさないと入らない行の境目が見た目で分からず、かえって不揃いに見える。名前の上限のほうを「まで」込みで取る。
- **ホバーで縮むのはメモの文字だけ。**縮める量もボタンの実測値 (`--buttons`) で渡す。
- **行の高さとボタンの高さは `manage.css` 冒頭の変数だけで決める。** 行の高さは名前の字送りから決まり、その上にボタンの 2 段が絶対配置で重なる。以前はボタン・期限の欄・× の高さがそれぞれの font-size / padding / border から暗黙に組み立てられていて、期限の欄を 1 つ変えただけで 2 段が枠をはみ出した。今は `--row-line` (名前 1 行) / `--row-pad-y` / `--chip-h` / `--chip-gap` / `--chip-inset` を 1 箇所に置き、守るべき式 (名前 1 行 + 上下余白 ≧ 2 段 + 逃げ) をコメントに書いてある。さらに `.tk-actions-row > *` に `height: var(--chip-h)` を掛けて、段に入るものは何であれその高さに抑える。行の `min-height` も同じ式から引くので、名前が短くても 2 段は必ず収まる。
- **行のボタンは 2 段。**上段はタスクそのものの扱いを変えるもの (これをやる / 待ち / 削除)、下段はタスクに情報を足すもの (期限 / メモ / ＋ サブ)。押す前に、どちらの種類の操作なのかが並びで分かる。**段はタスクの中身によらず常に 2 段**にしてある — ボタンが行によって上下に移ると、覚えた位置が使えなくなる。
- **集中中も Focus View から書き換えられる。** 既定では畳んであり、開いたぶんだけウィンドウが下端固定で上に伸びる。枠の高さは固定で、溢れた分はその中でスクロールする — 入力に合わせて伸び縮みさせると、打つたびにウィンドウが動いて落ち着かないため。
- 集中中の入力は、フォーカスが外れるのを待たず**入力が止まった 0.7 秒後に保存**する。画面を閉じずに時間切れになることがあるため。
- **本文の中の URL やパスは色が付き、Ctrl+クリックかダブルクリックで開く。**URL は下線、パスは点線。Ctrl を押しながらリンクの上に来るとカーソルが指になる (textarea は文字の位置を点から引けないので、下敷きの色付き部分の矩形で当てている)。押すと URL は**既定のブラウザ**、パスはエクスプローラーで開く。webview 内で遷移させるとアプリ自体が別のページに化けるため、`<a href>` は使わず外部に渡している。
- textarea は文字に色を付けられないので、**同じ字送りの下敷きを後ろに敷き、textarea 側の文字を透明にしている** (`LinkedTextarea`, `src/lib/NoteBody.tsx`)。見えている文字は下敷きのもの、打っているのは textarea。余白・フォント・折り返し・スクロール位置を textarea から写して重ねる。以前は本文の下にリンクを抜き出して並べていたが、本文の中で押せるなら二重に見せる必要はない。一時メモの行も同じ色付けで、そこは Ctrl 無しで押せる。
- **`C:\...` のようなローカルのパスと `\server\share` のネットワークのパスも押せる。**エクスプローラーで開く (ファイルならそのフォルダを開いて選択、フォルダならそのまま)。空白を含むパスは `"..."` で囲んであれば 1 本として拾い、囲んでいなければ空白で切る — どこまでがパスなのかを本文から当てるのは無理なので、書き手に引用符で教えてもらう。日本語の文の中に置かれることが多いので、句読点やかぎ括弧で切る。丸括弧はフォルダ名にも使う (「見積（2026）」「Program Files (x86)」) ので切らず、対になる開き括弧が無い末尾の閉じ括弧だけを文の側と見なして落とす。Rust 側はドライブ付きか UNC の形だけを受け、それ以外を Explorer に渡さない。本文から切り出したパスは後ろに文の続きが張り付いていることがある (「\server\share\wolです」) ので、画面側で末尾のひらがなを助詞と見なして落とし、Rust 側でも無ければ末尾から 1 文字ずつ削って実在するところまで戻る。それでも無ければ実在する親まで戻り、それも無ければ「開けませんでした」とリンクの下に出す (黙って何も起きないのが一番困る)。何を受けてどう解決したかは毎回 `data\startup.log` に `open_path ...` として残す — 会社の PC で開けないとき、手元で再現できなくても後から追えるように。コマンドは async にしてある。ネットワークのパスの存在確認は相手が応答しないと何秒も待つことがあり、同期コマンドだとその間 UI ごと止まる。

**完了と選択は色で分ける。** 同じ行に「完了にする」と「次にやる 1 件にする」という 2 つの意味が並ぶので、取り違えを防ぐ手当てが要る。

形では分けられない。四角いチェックボックスは「行の選択」に見えるが、丸にするとラジオボタン = やはり選択に見える。どちらの形も選択の意味を持ってしまう。

分けるのは色。**緑 (`--accent-break`) が完了、橙 (`--accent-focus`) が選択**で、アプリ全体で一貫させている。完了のチェックは触ると緑の枠と緑のチェックが出る (= 押した後の姿がそのまま見える) 一方、選択は「これをやる」ボタンと**行の左端の帯**が橙。押す前に、色でどちらの操作なのかが分かる。

それでも、チェックボックスを「選ぶ」の意味で押してしまう癖はなかなか抜けない。押し間違えて完了にしてしまう人向けに、設定の**「タスクのチェックボックスの意味」を「次にやる 1 件に選ぶ」**に切り替えられる。そうするとチェックは橙で光って押せば選択になり、行の「これをやる」ボタンが「✓ 完了」ボタンに入れ替わる (触ると緑)。色の意味は変えず、どの部品がどちらを受け持つかだけを入れ替える。完了した行のチェックは選べないので、そのまま「未完了に戻す」。

**選んだだけで開始しないとき、周りを伏せられる。** 会議中の片手間のように「1 件選ぶが、タイマーは回さない」使い方がある (ポモドーロに数えるべきではないし、Focus View も出したくない)。そのとき一覧に他のタスクの名前が並んでいると、選んだ 1 件をやりながら目に入って気が散る。設定の**「タスクを選択している間、他のタスクを薄くする」**を入れると、選択した瞬間に、選んだ 1 件とその親子以外の行・一時メモ・引き出しが薄くなる。薄さは「少し薄く / 薄く / ほぼ見えなく」から選ぶ。伏せるだけで消しはしないので、マウスを載せた行やキーボードで止まっている行はその間だけ元の濃さに戻り、書きかけの箱も薄くしない。選択を外すか開始すれば元に戻る。外すのは、タスク以外のどこかをダブルクリックするだけでよい (行の余白・一時メモ欄・見出し・下の帯)。選ぶのがダブルクリックなので、外すのも同じ手にしてある。選択中は余白のダブルクリックが「追加」ではなく「外す」になり、外れた後にもう一度押せば追加の箱が出る。専用のボタンは置かなかった。普段はいちいち押さず、既定 (薄くしない) のままにしておけば今までと変わらないため。

**一時メモはその場で書き直せる。** 割り込みは急いで書き留めるものなので、誤字も言葉足らずも残る。タスク名と同じく、押せばその場で直せる。貼り付けた依頼文が入っていることがあるので、入力は複数行を受ける (Enter で確定、Shift+Enter で改行 — Quick Capture と同じ)。

名前の要素は文字幅ぴったりに収めてある。行の全幅を占めると、名前の上での操作と行の上での操作の区別がつかなくなるため。

## 次の予定

会議までにポモドーロが 1 本入るかを毎回目算するのは、それ自体が判断の負担になる。時刻を入れておけば、アプリがその判断を引き受ける。

- 画面下端に「次の予定」の時刻を入れると、**まるごと入る本数**を出す。欄を押すと 15 分刻みの選択肢が開く — 時と分が 1 つの並びで出るので、細かく刻むと探す手間が増えるだけ。そのまま打てば 1 分単位で入る。 キーボードでは Space で一覧が開き、↑ ↓ で選んで Enter。閉じているときの ↑ ↓ は時刻の増減ではなく画面の移動に使う (数字を打てばそのまま入る)。標準の時刻ピッカーは `step` を無視して分を 1 分刻みで並べるので、選択肢は自前で出している。
- 1 本も入らないときは**開始ボタンを止め**、「細切れの作業か、次の予定の準備に使う時間です」と示す。閉じ込めはしないので「予定を無視して開始」から始められる。
- n 本に必要なのは `n * 集中 + (n - 1) * 休憩`。最後の 1 本のうしろに休憩は要らない。
- 予定の手前に**緩衝時間**(既定 3 分)を空ける。ポモドーロの終わりと会議の開始をぴったり合わせると、席を立つ時間も頭を切り替える時間も無い。設定で変えられる。
- 過ぎた予定は自動で消える。翌日に前日の予定が効いたままだと、理由の分からないまま開始ボタンが止まることになる。

ポモドーロは分割できないので、終わらないと分かっている 1 本は始めない、というのが原典の運用。半端な塊を混ぜると「自分の 25 分でどれくらい進むか」の感覚が育たなくなる。

## キーボードで一覧を歩く

マウスなら行に乗せればボタンが出るが、キーボードだと Tab で見えないボタンを渡り歩くことになる。そこで**行そのものに Tab で止まれる**ようにし (`tabIndex`)、止まっている行はマウスを乗せたときと同じ姿 (ボタンが出る) にしてある。

- ↑ / ↓ は画面を 2 つの縦の列と見て、その列で上下にあるものへ渡る。左の列は 設定 → 一時メモの ＋ → 一時メモの行 → 次の予定、右の列は 設定 → タスクの ＋ → タスクの行 → 待ち / 完了の引き出しの見出し (開いていればその中の行も) → 開始ボタン。行の中のボタンにいても、その行を今いる場所と見なして隣へ移る。→ / ← で行の中のボタンを順に (チェック → 完了/これをやる → 待ち → 削除 → 期限 → メモ → ＋ サブ)。← で最初のボタンから行に戻る。
- Enter か Space は、行の上ならダブルクリックと同じ「次にやる 1 件」にする。選んだらそのまま開始ボタンへ focus が移るので、Enter → Enter で始められる (選択を外したときは行に留まる)。ボタンの上ならそのボタンを押す。一時メモの行では書き直しに入る。
- どこにも止まっていないときに矢印を押すと、まず一番上の「設定」へ。タスクの列の一番下からさらに ↓ を押すと、タスクを選んでいれば開始ボタン、選んでいなければ (押せないので) 次の予定へ。
- タスクの行の上で ← を押すと一時メモの一覧へ、一時メモの右端のボタンでさらに → を押すとタスク一覧へ渡る。
- Esc でボタンから行へ。行の上か開始ボタンの上で Esc を押すと、選んでいるタスクを外す (選んでいなければ行から外れる)。
- 「止まっている」の判定は `:focus-visible` (キーボードで付いた focus だけ)。マウスのクリックで付いた focus まで数えると、押した後もボタンが出たままになる。行の中のボタンは `:has(:focus-visible)` で拾う。作りは `src/lib/keynav.ts` — 行の中 (← → Enter Esc) は一覧ごとの `rowNavHandler`、縦の並び (↑ ↓) は画面全体の `verticalNavHandler` に、止まれる場所を document 順の selector で渡してある。Enter で選んだ直後は行が描き直されて focus が外れるので、描き直し後に同じ行へ戻す。

Focus View も同じ作法で歩ける (`rowNavHandler` と `verticalNavHandler` をそのまま使う)。

- 集中中の「行」は、タスク名 (← → で 完了 / 待ち / メモ / 内訳、Enter で一時メモを書く) → 内訳の 1 件 (← → で チェック / 切替、Enter で切替) → メモ欄 (中では矢印は文字送り、Esc でタスク名へ戻る) → 待ちの入力 → 計測器のボタン列 (← → で 一時停止・中断・全画面、Enter で一時停止 / 再開)。
- 休憩中は、見出し (Enter でさっきまでのタスクの札を開閉) → さっきまでのタスク (← → で 完了にする / 待ちにする) → 整理中の 1 件 (← → で タスクへ / 後で / 削除、行の上の Enter は「後で」) → 計測器。
- 鳴る前に終わったときの 3 択は、ボタン列が 1 つの行 (← → で選び、行の上の Enter は推奨のもの)。候補の一覧は ↑ ↓ で 1 件ずつ。
- どこにも止まっていなければ、矢印でその画面の一番上 (タスク名 / 見出し / 3 択) へ。

期限のカレンダーは、**マウスで開いたなら日を押した時点で確定して閉じる**。押して選んだのなら、そこで決まっているのに欄が入力中のまま残るのは余計な一手になる。ただし「押して選んだ」のか「矢印で 1 日動かした」のかは、来る `change` からは見分けられない — カレンダーが開いている間、キーはブラウザのカレンダーが受け取ってページには届かないため。見分けられるのは**欄を開いたときの操作**で、マウスで開いたならカレンダーも押して選ぶ、キーボードで開いたなら矢印で歩いて Enter で決める、と見なしてよい (`lastInputWasPointer`)。打ち込み始めたら、以後は Enter か欄外で確定する。

期限のカレンダーは矢印キーで歩ける。ブラウザ標準のカレンダーは矢印で 1 日ずつ動くたびに `change` を出すので、そこで確定すると 1 歩目で欄が閉じてカレンダーも消えてしまう。値は控えるだけにして、**Enter (カレンダーが閉じた後にもう一度) か欄を離れたときに確定**する。待ちの「いつまで」も同じで、change では閉じない。

名前の編集欄は、表示と文字が 1px も動かないように合わせてある。欄は 1 行の input ではなく折り返す textarea (Enter は確定、改行は入れない) で、幅も表示と同じ (行ごとに測った `titleMax`) にし、期限・🍅・メモの手掛かりも編集中に消さない — 全幅に広げたり 1 行に伸ばしたり手掛かりを消したりすると折り返す位置が変わって行の高さが動き、下の行が跳ねる。表示は padding 3px / margin-left −3px で文字が行の左端に揃っているので、編集欄は枠線 1px のぶん padding を 2px にし、上下の枠線は負の margin で吸う。サブタスクは字が小さい (13px) ので、編集欄も同じ字にする。

## 定型タスク

「メール確認」「連絡の確認」のように型の決まったものは、一時メモ欄の下の引き出し「定型」に登録しておく。行の「追加」を押せば、その型から普通のタスクが 1 件追加される (一覧の先頭、期限はその日、名前の頭に ↻)。追加されたタスクはそれ以降ただのタスクで、定型を消しても残る。

**テンプレートと繰り返しは分けない。** 繰り返しは「周期の付いた定型」なので、データとしては 1 つの箱 (`routine`) で済む。周期は なし / 毎日 / 毎週 (曜日を複数) / 毎月 (日付)。周期が付いていれば、その日に自動で追加される。

自動で追加する決まり:

- **逃した日の分は取り戻さない。** 起動していなかった日の「メール確認」を今日 3 件積んでも意味が無い。起動時と、起動したまま日付が変わったときに「今日の分」だけを追加する。毎月のものだけは、その日を逃しても月内なら 1 回追加する (月 1 回のものは日付が多少ずれてもやる価値がある)。31 日指定で 30 日までの月は月末に読み替える。
- **同じ日に二重には追加しない** (`last_spawned_on`)。
- **前の分がまだ片付いていなければ、次を追加しない。** 未完了・着手中・待ちの「メール確認」が残っているのに翌日の分が追加されると、毎日のものが溜まっていく。
- **追加するとき、同じ定型の完了済みは「済み」の引き出しから外す** (status を `archived` に)。毎日「メール確認」が完了に積み上がると引き出しが定型で埋まる。今日の完了数は `completed_at` で数えているので影響しない。

作りは `routine` テーブル (`db.rs`) と、起動時 (`lib.rs`) / 日付が変わったとき (`timer.rs` の tick) の `spawn_due_routines`。判定は `Routine::is_due_on` に閉じてあり、単体テストで固定している。

## 元に戻す (Ctrl+Z) / やり直す (Ctrl+Y)

完了のチェックを押し間違えたときに慌てず戻せるように、管理画面の操作は Ctrl+Z で戻せる。完了 / 名前の変更 / 期限 / 削除 / 並べ替え / 待ちにする・解除 / メモの変更 / 追加 (タスク・サブタスク・一時メモ) / 一時メモの「タスクへ」「削除」「書き直し」。戻すと画面の下に「元に戻しました: 完了」と一瞬出る。戻しすぎたら Ctrl+Y (または Ctrl+Shift+Z) でやり直せる — 「やり直しました: 完了」。新しい操作をすると、やり直しの列は捨てる。

作りは、サーバー側に履歴を持たせるのではなく、**操作のたびに「その直前の状態に戻す手順」と「もう一度行う手順」を画面側で積む** (`src/lib/undo.ts`)。操作の直後に戻すためのものなので、これで足りる。アプリを閉じれば消える。待ちの編集とメモの編集は 1 回の編集で 1 つだけ積む — 途中の保存ごとに積むと、Ctrl+Z 1 回で半分しか戻らない。入力欄の中では Ctrl+Z をブラウザ自身の文字の取り消しに譲る。

戻せないもの: 「一時メモへ」(名前・メモ・サブタスクが 1 つの文章に畳まれるので、元の形が残らない)、Focus View の完了・待ち (タイマーの状態に絡む)。

## 緊急度 × 重要度の表

タスクが増えると、一覧の上から順に見ても優先順位が決まらない。かといって、普段の一覧に象限や優先度の列を足せば、集中中に見せないようにしている情報を毎日見せることになる。そこで**表は「たまに開いて見直す場」**と位置づけ、タスク欄の中で一覧と入れ替える。窓は増やさない。既定は一覧で、表にしたことは覚えない — 覚えると次に開いたときに表から始まってしまう。

- **緊急度は持たない。期限から決める** (2 日以内か過ぎていれば緊急)。別の項目として持つと「期限は明日だが緊急ではない」のような食い違いが起き、2 つを突き合わせる手間が毎回かかる。急ぎにしたいなら期限を入れる、という今までの言葉のままにする。
- **重要は 2 値。**段階を増やすと、付けるたびに迷う。列は `task.importance` を最初から持たせてあったのでマイグレーションは要らない。
- **マスの見出しは区分をそのまま出す** (「Ⅰ 緊急かつ重要：すぐやる」)。名前だけにすると、どのマスがどの区分なのかを覚えて読むことになる。象限の番号と、マスの隙間を通す十字の線も同じ理由 — 枠だけだと「箱が 4 つ並んでいる」ようにしか見えず、2 本の軸で切った 4 つの象限だと伝わらない。
- **マスごとに「次の一手」を 1 つだけ**置く (次にやる / 期限を付ける / 待ちにする / 一時メモへ)。アイゼンハワーの指示 (やる / 計画する / 任せる / やめる) を、既にある操作に対応させただけで、新しい概念は足していない。
- **上下のドラッグは印の付け外し、左右のドラッグは期限の付け替え。**左右で期限を外してしまうのはやり過ぎなので、今日 (緊急にする) か 1 週間後 (緊急でなくする) を仮に置き、そのままカレンダーを開いて決め直してもらう。
- 待ちのタスクは「任せる」のマスに薄く並べる。既に相手の番になっているので、印としてそこにあるのが自然。
- 「すぐやる」が 3 件以上なら見出しが警告色になる。ここが膨らんでいるのが「回っていない」合図。
- 表から集中は始めない。ダブルクリックで「次にやる 1 件」にして一覧に戻す。始めるのは今まで通り一覧の開始ボタン。
- 一覧では、重要の印を 🍅 の左に小さく出すだけにする。表を開かなくても、付けたことを思い出せればよい。

## 待ち

メールの返信待ち、他社の作業待ちなど、**タスクとしては閉じられないが自分では進められない**状態。

- 行の「待ち」ボタンで設定する。**何を待っているか**と**いつまで待つか**を一緒に取る。要因だけだと後から見て何を催促すればよいか分からず、日付だけだと誰に言えばよいか分からない。
- 設定した後は**「待ち」の表示をクリックすれば書き直せる**。タスク名やメモと同じで、直すのに専用のボタンを探させない。要因を Enter で確定すると**そのままカレンダーが開く**ので、催促の日まで一息で入れられる。ただし**催促の日が既に入っていれば開かない** — 要因を直しただけなので、Enter で確定して閉じる。
- 期限も催促の日も**曜日を添えて出す** (`9/14(月)`)。締切が平日かどうかで動き方が変わるので、月日だけでは毎回頭の中で数えることになる。
- **集中中でも Focus View の砂時計ボタンから待ちに回せる。**詰まったと分かるのは大抵やっている最中で、そのために管理画面へ戻らせると集中が切れる。入力は管理画面と同じ (要因 → Enter → カレンダー)。回した後は完了と同じ 3 択の流れに乗り、🍅 もその場で付く — 詰まったことで実績が減る設計にすると、正直に報告しない方向に歪む。
- 待ちのタスクは**「次にやる」候補から外れる**。手を動かせないため。着手対象に選んでいたものを待ちにすると、選択も外れる。集中が終わって Idle に戻るときも、待ちのまま選ばれ続けないように外す。
- 一覧からは畳んで「待ち N 件」の引き出しに回す。ただし**催促の日が来ているものがあれば、畳んだままでも見出しが警告色になる**。畳んで忘れるのが一番困るため。
- タスク自体の「期限」とは別項目。締切と「いつまでに返事が来なければ催促するか」は別物。

DB 上は `status = 'waiting'` と `waiting_for` / `waiting_until`。

## 完了したタスク

普段の一覧は「これからやるもの」だけにする。完了した親タスクは一覧から外し、タスク一覧の下の「完了したタスク N 件」を開いたときだけ並べる。

完了したサブタスクは、親がまだ進行中なら一覧に残す。進み具合として読めるほうがよいため。

## ゴミ箱

画面からの「削除」は消さずにゴミ箱へ入れる。誤って消したときに戻せるようにするため。

- 一時メモとタスクの両方から入るので、どちらの領域でもない**下の帯の左端に、箱の絵と件数だけの小さな印**を置き、押すとその上に板が開く。目立たせない — 消したものの置き場は、普段の視界に入らないほうがよい。中は「一時メモ」「タスク」に分けて並べる — ゴミ箱に入ると見た目が同じ 1 行になり、戻したときにどこへ現れるかが違うため。各行に「戻す」「完全に削除」、下に「空にする」。空のときはボタン自体を出さない。
- 戻すと**捨てる前の状態に返る** (`prev_status` を控えてある)。一時メモは一時メモに、完了したものは完了のまま。
- 親を捨てるとサブタスクも一緒に入り、戻すと一緒に戻る。ゴミ箱の一覧には親だけ並べる。
- **アプリの終了時に空にする。**起動時にも空にするので、強制終了で残った分もそこで片付く。長く貯める場所ではなく、直前の操作を取り消すための置き場という位置づけ。

## 仕組み上の注意

**タイマーの権威は Rust 側にある。** 残り時間は「終了予定の絶対時刻」から毎回引き算して求める。JS の `setInterval` はウィンドウが非表示・最小化されるとスロットリングされるため、フロントに計時を持たせると 25 分計ったつもりが静かにずれる。フロントは 200ms 間隔で飛んでくるスナップショットを描画するだけ。

**ウィンドウの出し入れも Rust 側から駆動する。** 管理画面が隠れている間はフロントから指示が出せないため。

**サブタスクは 1 階層のみ。** 無限階層にすると管理そのものがタスクになり、シングルタスク思想と逆行する。

**Focus View の常時最前面は設定で切れる。** 既定は有効。設定を変えたら、次のセッションを待たずに開いている Focus View へ即座に反映する。

**Focus View の半透明も設定で切れる。** ただし OS 側の透過はウィンドウ生成時にしか指定できないため、この設定だけは**次回起動で反映**される。そのため Focus View は `tauri.conf.json` ではなく `windows.rs` の `create_focus_window()` で生成している。CSS の地の濃さも同じ設定に追従させ、OS 側と見た目が食い違わないようにしている。

地の濃さは `rgba(20, 22, 26, 0.82)`。以前は 0.94〜0.96 で、透過を有効にしても無効にしても見た目がほとんど変わらず、設定が効いているのか判別できなかった。

**中断は記録する。** 集中中のタスク切り替えは「中断」として明示的に記録され、管理画面に日次で出る。摩擦をあえて残すことで、何に集中を切られているかが可視化される。

**計測器はフェーズが変わっても動かさない。** 集中でも休憩でも、時計は同じ場所に同じ大きさで出る。フェーズごとに時計の位置と大きさが変わるようでは、残り時間を測る道具として信用できない。変わるのは上の領域の中身だけ (タスク名 / triage / 3 択)。

**Focus View はタスク名が先で、計測器 (タイマー・操作・進捗) は下段。** 主題はタスクで、タイマーはそれを測る道具なので、上から読む順序と一致する。

実利もある。この窓は下端を固定して上に伸びるので、タイマーを下段に置けば**メモや 3 択を開いてもタイマーが画面上で動かない**。上段に置くと、窓が伸びるたびに目で追う対象がずれる。進捗バーもタイマーと同じ部品なので下段にまとめている。

**サブタスクは既定で畳む。** タスク名の右端に開閉アイコンだけを置き、押すと全件並ぶ。その場で着手先の切り替えと完了ができる。件数まで出すと畳んでいる意味が薄れるので、アイコンだけに絞っている (件数はツールチップで出す)。

アイコンは**幹から 2 本枝が出て、その先にタスクの四角がぶら下がる形**。三角形は同じ大きさの再生ボタンと紛れるうえ、「この下に内訳がある」ことを絵で示せない。枝の先を線のままにすると今度はただの記号に見えるので、ぶら下がっているのが「タスク」だと分かる形にしてある。開いたかどうかは向きではなく色で出す — 回すと、今度は何のアイコンだったのか分からなくなる。

サブタスクは「別の仕事」ではなく約束した 1 件の内訳なので、一覧を見せないという方針とは衝突しない。ただし常時開いておくと結局一覧になるため、既定は畳んだまま。フェーズや着手先が変わったら自動で畳む。

**一覧の末尾にも落とし先を置く。** 行だけを落とし先にしていると最下段に手が届かない。最後の親がサブタスクを持っていれば、一番下に見えている行はそのサブタスクで、その下端に落としても「同じ親の弟」= サブタスクになる。つまり**親タスクを一番下に置けない**。行の外に一段、当たりだけを置いて逃げ道にしている。

**枠も説明も出さない。**かかったときに、行に落とすときと同じ挿入線を引くだけ。線が行の全幅なら親タスク、サブタスクの位置なら内側で短くなるので、**どこに入るかは線の長さが伝える**。破線の枠に「ここに落とすと…」と書くような案内は要らない。

**管理画面は `dragDropEnabled: false`。** これを既定の true のままにすると、OS のファイルドロップ処理がドラッグを横取りし、ページ内の並べ替えが一切効かなくなる (掴んだ瞬間に禁止マークが出る)。ファイルのドロップを受ける予定はないので、無効にしてよい。

**掴む場所はグリップに限る。** 行ごと掴めるようにすると、名前のクリック (= 編集) や文字の選択と取り合いになる。

**並べ替えは並びを毎回振り直す。** 隙間の中間値を入れていく方式だと、繰り返すうちに桁が詰まって順序が壊れる。移動のたびに同じ親の下を 1024 刻みで振り直すほうが単純で安全。

**スクロールする一覧は、子に `flex: none` を付ける。** 縦並びの flex でこれを忘れると、収まらないときにスクロールせず一つひとつが潰れて文字が読めなくなる。

**同じ仕事の中での切り替えは「中断」に数えない。** 兄弟サブタスク間や親と子の移動は、文脈が続いているので集中を切られたわけではない。別の系統へ飛ぶときだけ中断として記録する。この線引きは `same_work()` に切り出してテストで固定した。

**タスク名は窓の幅を丸ごと使う。** 時計とボタンに左右を挟まれる横並びだと、少し長い名前で読めなくなる。

**伸縮する領域とボタンは分ける。** 本文とボタンを同じ伸縮領域に置くと、長い貼り付けのときにボタンが押し出されて押せなくなる。本文だけをスクロール領域にして、ボタンはその外に出す。

**IME の変換中かどうかは自前で持つ。** `KeyboardEvent.isComposing` は当てにならない。Focus View (装飾なし・常時最前面の窓) では、日本語を確定した後の Enter でも `true` のままになることがあり、「Enter で次へ進む」が永久に動かなくなる。`compositionstart` / `compositionend` は確実に届くので、`useComposition()` でそちらを見る。

**カレンダーはキーを押した処理の中で開く。** `showPicker()` はユーザー操作の最中でないと拒否される。状態を更新して描画後の `useEffect` で呼ぶ形にすると、フォーカスは移るのにカレンダーだけ開かない。日付欄には `onFocus` でも開くようにしてあるので、Enter で移ってきても Tab でもクリックでも同じように開く。

**Focus View は最大化できないようにしてある。** ドラッグ領域のダブルクリックは Windows ではタイトルバーと同じ扱いになり、窓を最大化する。最大化した窓には `set_size` が効かないため、一度そうなると以降どのフェーズでも高さが直らない。しかもこのアプリはトレイに常駐するので、終了するまでその状態が残り続ける。`maximizable(false)` で入り口を塞ぎ、`resize_focus()` でも毎回 `unmaximize()` を試みている。

**Focus View の幅は固定値。** 現在の幅を引き継いで計算すると、何かの拍子に広がったときその幅が居座り続ける。

**当たりの高さを当てるのは、隠れていた窓を出すときだけ。** 出しっぱなしの窓に当て直すと、フロント側が測った高さと競合する。フロントは `timer://phase` を受けた時点で中身を測って寄せてくるので、その後から Rust 側が当たりを書くと当たりの方が残り、下端固定ゆえに**窓が上にずれたまま居座る**。表示が変わらない操作 (暗幕の解除など) でも起きていた。

**Focus View は中身の高さに合わせて、下端を固定して上に伸ばす。** 表示する中身は状況で変わる (1 行 / triage / 3 択 / 候補 / メモ) ので、高さを決め打ちにすると必ずどこかで見切れる。`ResizeObserver` で中身の高さを監視し、ウィンドウ側を追従させている。また、この窓は画面の右下に置くので、左上を固定して下に伸ばすと画面外にはみ出して増えた部分が見えなくなる。

**状態は `Builder::manage()` で登録する。** `setup()` の中で `app.manage()` すると、WebView2 の初期化中にメッセージループが回った隙にフロントの `invoke` が先に処理され、`state() called before manage()` で落ちることがある。debug ビルドは unwind するので生き残り、`panic = "abort"` のリリースビルドだけが死ぬ、という気付きにくい形で出る。

## 休憩明けは管理画面を前に出す

休憩が終わって Idle に戻るとき、管理画面を `set_focus` するだけでは前に出ない。Windows は、前面にいるのが別のアプリのときは他のプロセスからの前面化を拒む — 休憩明けはまさにその状態 (休んでいる間に別の作業をしている)。そこで、その瞬間だけ「常に手前」にして重なり順の一番上へ持ち上げ、すぐ外す (`windows::raise`)。外しても重なり順は残る。

## 窓はすべて起動時に作る

暗幕の窓も起動時に隠したまま作っておく。Windows では、窓の生成をメインスレッドの同期コマンドの中から呼ぶと WebView2 の生成がメッセージループを待って固まる (Tauri の既知の制約)。休憩に入る経路には「休憩へ」ボタン = 同期コマンドがあるので、そこで初めて暗幕を作る形にすると、その休憩で UI ごと止まる — 暗幕が掛からない、ボタンが効かない、一時メモの整理が出ない、窓の高さが合わない、が同時に起きる。タイマーが自然に切れて入る休憩 (別スレッド) では起きないので、気づきにくい。
