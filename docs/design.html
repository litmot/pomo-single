PomoSingle

ポモドーロタイマーと一体になった、シングルタスクのためのタスク管理アプリ。 集中しているあいだは今やる 1 件だけを見せ、割り込みと思いつきは一時メモに逃がし、 休むことを既定にする。

Platform Windows 11 / 単体 exe Stack Tauri 2 + React + SQLite Phase 2 / 3
Premise

管理するのはタスクではなく、注意

普通の To-Do リストは、溜まったタスクを全部見せる。一覧は見直すときには要るが、手を動かしているあいだは、それ自体が割り込みになる。 かといって、思いついたことを書き留める場所が手元になければ、それは頭の中に居座って同じだけ注意を奪う。

注意を奪うものは一覧だけではない。休めていないことと、自分では進められない仕事を抱えていることも同じように注意を持っていく。 PomoSingle はこれらにそれぞれ居場所を与え、その土台として、ポモドーロという測る単位を崩さない。 以下の設計はすべて、次の 5 つの原則から導かれている。

  1. 集中中に見せるのは 1 件だけ一覧は視界の外に置く。画面を「何が見えるか」で分ける。
  2. 書き留める場所は常に手元に、処理する時間は休憩に割り込みは 1 秒で書き留め、振り分けは休憩のときにまとめて行う。
  3. ポモドーロは測る単位。崩さない長さは変えない、途中で切らない、早く終えても 1 回に数える。
  4. 休むことを既定にする休憩は勝手に始まり、次の集中は勝手には始まらない。休憩中は画面を暗くする。
  5. 自分では進められない仕事に居場所を未完了でも完了でもない「待ち」という状態を用意し、一覧から外す。

3 · Unit

ポモドーロは測る単位。崩さない

タスクの 🍅 と今日のポモドーロ数は、「自分の 25 分でどれくらい進むか」という感覚を育てるための唯一の手がかりになる。 1 🍅 が「10 分のことも 25 分のこともある」となった時点で、その手がかりは使えなくなる。 だから1 🍅 = 標準の集中 1 本という単位を、次の 3 つで守る。

長さはタスクに合わせて変えない

長さは自分の設定であって、タスクの性質ではない。タスクごとに変えると「このタスクは 3 ポモドーロ」という見積りが成り立たなくなる。 25 分が重くて始められないときのために短い集中 (10 分) を別に用意したが、これはポモドーロには数えない。 🍅 も付かず、長い休憩の周期にも入らず、後に休憩も挟まない。開始ボタンの隣に控えめに置き、主役にはしない。

鳴る前に終わっても、タイマーは止めない

ポモドーロは分割できない。ただし「残り 20 分あるが見直すものがない」という状況は実際に起きるので、 タイマーは止めずに残り時間の使い道だけを聞く。残りが多ければ次のタスクへ (同じ 1 本を引き継ぐ)、 少なければ休憩へ、その間なら見直しを勧める。決めるのは本人。待ちにしたときも同じ流れに乗る。

早く終えても、詰まっても 1 回に数える

終わらせた人が実績で損をする作りは、必ず「終わっても報告しない」方向に歪む。完了は「中断」にも数えない。 中断は「何に集中を切られたか」を見るための数字で、集中中に別の系統のタスクへ切り替えたときだけ記録する。 同じ仕事の内訳の中での移動は数えない。

4 · Rest

休むことを既定にする

休憩が飛ぶのは意志の弱さではなく、既定値の問題である。画面がそのままなら手も止まらない。 そこで、フェーズの遷移を 1 か所だけ意図的に非対称にしてある。集中の後は自動で休憩に入るが、休憩の後は自動で次の集中に入らない。 休息は放っておいても取れるべきで、次の 1 件に手を付けるかどうかは毎回自分で決めるべきだから。 続きをやるのが明らかなときは、開始ボタンが「同じタスクでもう一度」に変わるので、選び直す手間はない。

休憩中はモニタ全体に暗幕をかける。3 秒かけてゆっくり暗くなるので、驚かせるのではなく「そろそろ手を止める時間だ」と伝わる。 クリックは素通しするので、急ぎの連絡が来ても逃げ場はある。残るのは居心地の悪さだけで、続けようと思えば続けられる。 それでも既定は入れ替わる。休むのが普通で、続けるのは無理に押し切る行為になる。 PC で休む (動画を見る、調べ物をする) のも休憩なので、Focus View のボタンでその場で外せる。外したことはその休憩の間だけ覚え、次の休憩ではまた掛かる。

休憩中はさっきまでのタスク名を見せない。名前が目に入ると頭がそこに戻る。 「あれはもう終わっていた」「返事待ちだった」と気づいたときのために、見出しの端の小さな札を押したときだけ開き、完了か待ちにできる。 進捗バーも休憩中だけ逆向きに減らす。休みは積み上げるものではなく使い切るものだから。

5 · Waiting

自分では進められない仕事に居場所を

メールの返信待ち、他社の作業待ち。これを未完了の山に置いたままにすると、一覧で目に入るたびに「今日はできない」と判断し直すことになる。 かといって完了にはできない。待ちはそのための 3 つ目の状態で、待ちのタスクは「次にやる」候補から外れ、一覧では引き出しに畳まれる。

待ちにするときは、何を待っているかといつまで待つかの両方を記入する。 理由だけでは後で何を催促すればよいか分からず、日付だけでは誰に言えばよいか分からない。 催促の日が来たものがあれば、畳んだままでも見出しが警告色になる。畳んで忘れるのが一番困るからだ。 詰まったと分かるのはたいてい作業中なので、Focus View からもそのまま待ちにできる。

Decisions

原則を支える個別の判断

計時は Rust 側で行う

残り時間は「終了予定の時刻」から毎回引き算する。ブラウザの setInterval はウィンドウが隠れると間引かれるため、 フロントに計時を持たせると 25 分のつもりが静かにずれる。フロントは届いたスナップショットを描くだけ。

時計は動かさない

集中でも休憩でも、時計は同じ場所に同じ大きさで出る。フェーズごとに位置が変わるようでは、残り時間を測る道具として信用できない。 Focus View は下端を固定して上に伸びるので、メモや選択肢を開いても時計は動かない。

完了と選択は色で分ける

一覧の行には「完了にする」と「次にやる 1 件にする」が並ぶ。形では分けられない (四角も丸も選択に見える) ので色で分け、 緑が完了、橙が選択。押し間違える人向けに、チェックボックスの意味を「選ぶ」に入れ替える設定もある。

サブタスクは 1 階層まで

階層を無制限にすると、構造を整えること自体がタスクになる。1 階層なら、Focus View に添える「次の 1 件」も一意に決まる。

入力は流れの中で聞く

タスクを追加した直後にカレンダーが開く。待ちの理由を Enter で確定すると、そのまま催促日のカレンダーに移る。 後から行を探してクリックし直す手間を作らない。入れなければそのまま次に進む。

型の決まった仕事は定型として登録する

「メール確認」のような毎日の仕事は、定型に登録しておけば押すだけでタスクになり、周期を付ければその日に自動で追加される。 逃した日の分は積まず、前の分が残っていれば次を出さない。毎日のものが溜まっていく状態を作らないため。

ホットキーは諦めない

グローバルホットキーは、他のアプリが同じキーを使っていれば OS に拒否される。Quick Capture が使えないとこのアプリの運用自体が成り立たないので、 候補を順に試して空いているキーを使い、設定に書き戻して通知する。

消したものは戻せる

振り分けの途中で押し間違えることはある。削除はゴミ箱に入り、元の状態のまま戻せる。管理画面の操作は Ctrl+Z で戻せる。

Data & Distribution

データと配布

SQLite の単一ファイル。ポモドーロの実績を後から分析したくなるので、JSON ではなく最初から DB にしてある。 主なテーブルは task (状態は inbox / todo / doing / waiting / done)、session (1 本ごとの記録。やり切らなかったものも終わり方と一緒に残す)、 routine (定型)、setting。壊れた設定値は既定値に戻し、設定が原因で起動できない状態にはしない。

保存先は、exe と同じ階層に書き込める data/ があればそこ (ポータブル)、なければ %LOCALAPPDATA%\PomoSingle\。 実際に書いてみて確かめる。Windows では ACL の事前判定が当てにならないため。

フロントエンドは exe に埋め込まれるので、PomoSingle.exe 1 つをコピーすれば動く。インストールも管理者権限も要らない。

未署名 exe は環境に依存する

自前ビルドは署名されていないため、初回実行時に SmartScreen の警告が出る。組織のポリシー (AppLocker / WDAC / EDR) によっては実行自体が止められる。 配布形態を決める前に、実機で一度試しておくのが確実。
