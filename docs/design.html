PomoSingle

ポモドーロタイマーと連動した、シングルタスク運用のためのタスク管理アプリ。 集中中は今やること 1 件だけを見せ、割り込みと思いつきは一時メモに逃がし、 休憩は取らせる側に倒す。

Platform Windows 11 / スタンドアロン exe Stack Tauri 2 + React + SQLite Phase 2 / 3
Premise

管理するのはタスクではなく、注意

既存の To-Do リストは、溜まったタスクを全部見せる。一覧はレビューには要るが、手を動かしている間は割り込みそのものになる。 逆に、思いついたことを書き留める場所が手近になければ、それは頭の中に居座って同じだけ注意を食う。

この 2 つは相反しない。書き留める場所は常に手の届く範囲に、読み返す場所は集中中の視界の外に置けばよい。 それをアプリの構造で強制するのが PomoSingle の目的で、以下の設計はすべてここから導かれている。

注意を食うのは一覧だけではない。休めていないことも、自分では進められない仕事を抱えていることも、 同じように注意を持っていく。この 2 つにもそれぞれ居場所を与えてある。

分数と長休憩の間隔は設定で変えられる。フェーズの遷移で 1 つだけ意図的に非対称にしてあるのは、 集中の後は自動で休憩に入るが、休憩の後は自動で次の集中に入らない点。休息は放っておいても取れるべきで、 次の 1 件に手を付けるかどうかは毎回自分で決めるべきだから。

ただし、続きをやるのが明らかなときまで選び直させる必要はない。休憩明けに着手中のタスクが残っていれば、 開始ボタンが「同じタスクでもう一度」に変わる。自動では始めないが、選び直す手間は無い。

Rest

休憩は、取らせる側に倒す

休憩が飛ぶのは意志の弱さではなく、既定値の問題である。画面がそのままなら手も止まらない。 そこで休憩中はモニタ全体に暗幕をかける。3 秒かけてゆっくり落ちるので、 驚かせるのではなく「そろそろ手を止める時間だ」と身体に伝える。

クリックは素通しする。手を縛ってしまうと、急ぎの連絡が来たときに逃げ場が無い。 残すのは居心地の悪さだけで、続けようと思えば続けられる。それでも既定が反転する — 休むのが普通で、続けるのは押し切る行為になる。

PC で休む(動画を見る、調べ物をする)のも休憩なので、Focus View のボタンで暗幕をその場で外せる。 外したことはその休憩の間だけ覚え、次の休憩ではまた掛かる。休憩ごとに判断させるためで、 一度外したことを既定にはしない。濃さは 4 段から選べる。掛けるのは 3 秒、引くのは 0.8 秒 — 掛けるのは合図、引くのは後始末だから。

進捗バーも休憩中だけ向きが逆で、残りが減っていく。休みは積み上げるものではなく使い切るもので、 同じ向きに伸ばすと終わりに近づくほどバーが満ちて、達成感のような読み違えを招く。

Early finish

鳴る前に手が空いたら

原典には答えがある。ポモドーロは分割できない — 始まったら鳴るまで走らせ、 余った時間は overlearning(見直し・反復・小さな改善)に充てる。止めて次に行くのではない。

枠を可変にすると、25 分がタスクの長さに引きずられて「自分の 25 分でどれくらい進むか」の感覚が育たず、 実績データも意味を失う。一方で、残り 20 分あって見直すものが無い状況は現実に起きるので、 杓子定規に当てても机の前で固まるだけになる。そこでタイマーは止めず、残り時間の使い道だけを聞く。

推奨は残り時間から決まる。決めるのは本人
選択肢 何が起きるか 推奨されるとき
見直す 同じタスクのまま「見直し」表示で鳴るまで走る 残り 4〜9 分
次をやる 候補 3 件から選び、同じセッションを引き継いで次の 1 件へ。終了予定時刻は動かさない 残り 10 分以上
休憩へ セッションを終えて休憩に入る 残り 3 分以下

この分岐に入るのは、完了したときだけではない。待ちに回したときも同じ流れに乗る — 手がその場で空くという点は同じで、空いた時間を放置させる理由がないため。 ただし待ちのときは「見直す」を出さない。相手の番になっている仕事は磨き直せないので、選ばせても手が止まるだけになる。

候補の並び順は、手を離したのがサブタスクなら同じ親の未完了サブタスクを最優先 — 文脈が続いているので切り替えコストが最も低い。次に期限の近い順で、期限なしは最後に回す。 Focus View に一覧を出すのはここだけで、これは決断の瞬間だけの表示であり、常時見えている情報ではない。

完了は中断ではない

中断カウントは「何に集中を切られたか」を見るための数字。約束を果たしたことでこれを汚してはいけない。

早く終えても、詰まっても 1 回

タスクを終わらせた人が実績で損をする設計は、必ず「終わっても報告しない」方向に歪む。詰まったときも同じ。 計上は 1 ブロック = 1 ポモドーロを保ち、タスク側の 🍅 はそのブロック中に着手した各タスクに 1 つずつ付ける。

Waiting

閉じられないが、自分では進められない

メールの返信待ち、他社の作業待ち。これを「未完了」の山に置いたままにすると、 毎回一覧で目に入っては「今日はできない」と判断し直すことになる。かといって完了にはできない。 待ちはそのための 3 つ目の状態である。

待ちにするときは何を待っているかといつまで待つかを一緒に取る。 要因だけだと後から見て何を催促すればよいか分からず、日付だけだと誰に言えばよいか分からない。 タスク自体の「期限」とは別項目で、締切と「いつまでに返事が来なければ催促するか」は別物として扱う。

待ちのタスクは「次にやる」候補から外れ、一覧からは畳んで引き出しに回る。手を動かせないため。 ただし催促の日が来ているものがあれば、畳んだままでも見出しが警告色になる — 畳んで忘れるのが一番困る。詰まったと分かるのは大抵やっている最中なので、 Focus View の砂時計ボタンからもそのまま待ちに回せる。

Focus View

同じ並びの、2 つの寸法

Focus View には小窓と全画面の 2 つの姿がある。中身と並びはまったく同じで、変えるのは寸法だけ。 並びまで変えると、小窓と全画面で別のアプリになってしまう。

既定
右下の小窓
装飾なしの 380px 幅。画面の隅に置いたまま作業する。半透明と常時最前面は設定で切り替えられる。
補助モニタがあるとき
モニタ 1 枚を全画面で覆う
チャットの通知や開いたままのブラウザごと覆い隠す。広げた先は覚えるので、次のセッションからも同じモニタに出る。

どちらの姿でも、タスクに付いている操作はタスク名の隣(完了 → 待ち → メモ → 内訳)、 タイマーに関わる操作は下段の計測器に分かれている。 窓は下端を固定して上に伸びるので、メモや 3 択を開いてもタイマーは画面上で動かない。

Decisions

効いている設計判断

計時の権威は Rust 側

残り時間は「終了予定の絶対時刻」から毎回引き算して求める。JS の setInterval は ウィンドウが非表示・最小化されるとブラウザ側でスロットリングされるため、フロントに計時を持たせると 25 分計ったつもりが静かにずれる。フロントは 200ms 間隔で届くスナップショットを描くだけ。

計測器は動かさない

集中でも休憩でも、時計は同じ場所に同じ大きさで出る。フェーズごとに位置と大きさが変わるようでは、 残り時間を測る道具として信用できない。変わるのは上の領域の中身だけ(タスク名 / 振り分け / 3 択)。

残件数は既定で伏せる

「あと 3 件ある」と見えてしまえば、それ自体が割り込みになる。Focus View が伝えるのは 「何かが入った」という事実だけで、量は伝えない。件数表示は設定でオンにできる。

完了と選択は色で分ける

一覧の行には「完了にする」と「次にやる 1 件にする」が並ぶ。形では分けられない — 四角いチェックボックスは行の選択に見え、丸にすればラジオボタン、やはり選択に見える。 分けるのは色で、緑が完了、橙が選択。触れば押した後の姿が色で出るので、言葉で補う必要がない。

サブタスクは 1 階層まで

無限階層にすると、構造を整えること自体がタスクになる。1 階層に制限すると、 Focus View に添えるサブタスクが常に「次の 1 件」に一意に決まるという副産物も得られる。

落とし先は線が伝える

並べ替えは行の端に落とせば挿入、中央に落とせばサブタスク。一覧の末尾にも見えない落とし先を置いてある — 最後の親がサブタスクを持っていると、行だけでは親タスクを一番下に置けないため。 案内文は出さず、挿入線の長さでどの階層に入るかを示す。

タスク切り替えに摩擦を残す

集中中の切り替えは「中断」として明示的に記録され、日次で集計される。 手間をゼロにしないことで、何に集中を切られているかが後から可視化される。 ただし同じ仕事の内訳の中での移動は中断に数えない。

資料は仕事のそばに置く

依頼のメール文や参照 URL をタスクに持たせ、集中中も Focus View から読み書きできる。 ただし既定では畳んでおく — 常に見えていれば、それは読むべきものとして注意を引き続ける。 必要なときに手が届くことと、常に視界にあることは別物として扱う。

同じ操作には同じ絵

メモ・待ち・内訳のアイコンは Focus View と管理画面で共用する。画面ごとに描き分けると、 「集中中に押したあのボタン」が一覧のどれなのか毎回文字を読み直すことになる。

入力は流れの中で聞く

タスクを追加した直後にカレンダーを開く。待ちの要因を Enter で確定すれば、そのまま催促日のカレンダーへ移る。 あとから行を探してクリックし直す手間を作らない。入れなければそのまま次に進む。

ホットキーは諦めない

グローバルホットキーの登録は、他のアプリが同じキーを握っていれば OS に拒否される — 実際に開発機では CtrlAltSpace が既に使われていた。 Quick Capture が使えないとこのアプリの運用自体が崩れるので、候補を順に試して空いているキーを採用し、 採用したキーを設定に書き戻して通知する。「登録できませんでした」で終わらせない。

マトリックスの列は最初から持つ

緊急度 / 重要度の UI は Phase 3 に回すが、task テーブルには urgency / importance 列を最初から置いた。後から列を足すマイグレーションを避けるため。

Data

永続化

SQLite の単一ファイル。ポモドーロの実績を後から分析したくなるため、最初から JSON ではなく DB にしてある。 スキーマの変更は PRAGMA user_version で段階的に当てる。

テーブル 持つもの 要点
task title / note / status / parent_id / sort_order / due / waiting_for / waiting_until / trashed_at / urgency / importance / actual_pomodoros status は inbox → todo → doing → done に waiting を加えた 5 つ。Quick Capture は必ず inbox に入る
session task_id / kind / started_at / ended_at / completed / interrupt_count / planned_ms / outcome やり切らなかったセッションも completed = 0 で残す。outcome は終わり方(rang / done_early_break / skipped / abandoned)
setting 分数 / 長休憩の間隔 / ホットキー / 最前面 / 半透明 / 暗幕と濃さ / 全画面 壊れた値では既定値に落ちる。設定が原因で起動不能にしない

保存先は 2 段構え。exe と同じ階層に書き込み可能な data/ があればそこを使い(ポータブルモード)、 なければ %LOCALAPPDATA%\PomoSingle\ に退避する。判定は実際に書いてみて確かめる — Windows では ACL の事前判定が当てにならないため。

捨てたタスクはゴミ箱に移り、元の状態を覚えたまま戻せる。消えて困るのは、振り分けの途中で押し間違えたときだから。

Distribution

会社の PC に持ち込むこと

Tauri はフロントエンドを exe に埋め込むので、PomoSingle.exe 1 つをコピーすれば動く。 インストール不要・管理者権限不要で、実体は約 5 MB。WebView2 ランタイムは Windows 11 に標準搭載されている。 ユーザー領域にインストールする NSIS インストーラも同時に出力される。

未署名 exe は環境に依存する

自前ビルドは署名されていないため、初回実行時に SmartScreen の警告が出る。 組織のポリシー(AppLocker / WDAC / EDR)によっては実行自体がブロックされる。 これはスタックの選択とは無関係に発生するので、配布形態を確定させる前に実機で 1 度試しておくのが確実。
