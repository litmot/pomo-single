PomoSingle

ポモドーロタイマーと連動した、シングルタスク運用のためのタスク管理アプリ。 集中中は今やること 1 件だけを見せ、思いついたことと割り込みは一時メモに逃がして、休憩時にまとめて振り分ける。

Platform Windows 11 / スタンドアロン exe Stack Tauri 2 + React + SQLite Phase 1 / 3
Premise

管理するのはタスクではなく、注意

既存の To-Do リストは、溜まったタスクを全部見せる。一覧はレビューには要るが、手を動かしている間は割り込みそのものになる。 逆に、思いついたことを書き留める場所が手近になければ、それは頭の中に居座って同じだけ注意を食う。

この 2 つは相反しない。書き留める場所は常に手の届く範囲に、読み返す場所は集中中の視界の外に置けばよい。 それをアプリの構造で強制するのが PomoSingle の目的で、以下の設計はすべてここから導かれている。

Focus View は装飾なしの小型ウィンドウで、画面の隅に置いたまま作業する。常に最前面に出すかは設定で切り替えられる(既定は有効)。 集中フェーズに入ると Manage View は自動で隠れ、Idle に戻ると再び前に出る。この出し入れは Rust 側から駆動する — 管理画面が隠れている間、フロントエンドからは指示が出せないため。

Early finish

鳴る前にタスクが終わったら

原典には答えがある。ポモドーロは分割できない — 始まったら鳴るまで走らせ、 余った時間は overlearning(見直し・反復・小さな改善)に充てる。 止めて次に行くのではない。

枠を可変にすると、25 分がタスクの長さに引きずられて「自分の 25 分でどれくらい進むか」の感覚が育たず、 実績データも意味を失う。一方で、残り 20 分あって見直すものが無い状況は現実に起きるので、 杓子定規に当てても机の前で固まるだけになる。そこでタイマーは止めず、残り時間の使い道だけを聞く。

推奨は残り時間から決まる。決めるのは本人
選択肢 何が起きるか 推奨されるとき
見直す 同じタスクのまま「見直し」表示で鳴るまで走る 残り 4〜9 分
次をやる 候補 3 件から選び、同じセッションを引き継いで次の 1 件へ。終了予定時刻は動かさない 残り 10 分以上
休憩へ セッションを終えて休憩に入る 残り 3 分以下

候補の並び順は、完了したのがサブタスクなら同じ親の未完了サブタスクを最優先 — 文脈が続いているので切り替えコストが最も低い。次に期限の近い順で、期限なしは最後に回す。 Focus View に一覧を出すのはここだけで、これは決断の瞬間だけの表示であり、常時見えている情報ではない。

完了は中断ではない

中断カウントは「何に集中を切られたか」を見るための数字。約束を果たしたことでこれを汚してはいけない。

早く終えても 1 回として数える

タスクを終わらせた人が実績で損をする設計は、必ず「終わっても報告しない」方向に歪む。 計上は 1 ブロック = 1 ポモドーロを保ち、タスク側の 🍅 はそのブロック中に着手した各タスクに 1 つずつ付ける。

Decisions

効いている設計判断

計時の権威は Rust 側

残り時間は「終了予定の絶対時刻」から毎回引き算して求める。JS の setInterval は ウィンドウが非表示・最小化されるとブラウザ側でスロットリングされるため、フロントに計時を持たせると 25 分計ったつもりが静かにずれる。フロントは 200ms 間隔で届くスナップショットを描くだけ。

残件数は既定で伏せる

「あと 3 件ある」と見えてしまえば、それ自体が割り込みになる。Focus View が伝えるのは 「何かが入った」という事実だけで、量は伝えない。件数表示は設定でオンにできる。

サブタスクは 1 階層まで

無限階層にすると、構造を整えること自体がタスクになる。1 階層に制限すると、 Focus View に添えるサブタスクが常に「次の 1 件」に一意に決まるという副産物も得られる。

タスク切り替えに摩擦を残す

集中中の切り替えは「中断」として明示的に記録され、日次で集計される。 手間をゼロにしないことで、何に集中を切られているかが後から可視化される。

資料は仕事のそばに置く

依頼のメール文や参照 URL をタスクに持たせ、集中中も Focus View から読み書きできる。 ただし既定では畳んでおく — 常に見えていれば、それは読むべきものとして注意を引き続ける。 必要なときに手が届くことと、常に視界にあることは別物として扱う。

期限は追加した流れで聞く

タスクを追加した直後にカレンダーを開く。期限を入れるためだけに、あとから行を探して クリックし直す手間を作らない。入れなければ期限なしのまま次の入力に戻る。

ホットキーは諦めない

グローバルホットキーの登録は、他のアプリが同じキーを握っていれば OS に拒否される — 実際に開発機では CtrlAltSpace が既に使われていた。 Quick Capture が使えないとこのアプリの運用自体が崩れるので、候補を順に試して空いているキーを採用し、 採用したキーを設定に書き戻して通知する。「登録できませんでした」で終わらせない。

マトリックスの列は最初から持つ

緊急度 / 重要度の UI は Phase 3 に回すが、task テーブルには urgency / importance 列を最初から置いた。後から列を足すマイグレーションを避けるため。

Data

永続化

SQLite の単一ファイル。ポモドーロの実績を後から分析したくなるため、最初から JSON ではなく DB にしてある。

テーブル 持つもの 要点
task title / status / parent_id / sort_order / due / urgency / importance / actual_pomodoros status は inbox → todo → doing → done。Quick Capture は必ず inbox に入る
session task_id / kind / started_at / ended_at / completed / interrupt_count / planned_ms / outcome やり切らなかったセッションも completed = 0 で残す。outcome は終わり方(rang / done_early_break / skipped / abandoned)
setting 分数 / 長休憩の間隔 / ホットキー / 件数表示 壊れた値では既定値に落ちる。設定が原因で起動不能にしない

保存先は 2 段構え。exe と同じ階層に書き込み可能な data/ があればそこを使い(ポータブルモード)、 なければ %LOCALAPPDATA%\PomoSingle\ に退避する。判定は実際に書いてみて確かめる — Windows では ACL の事前判定が当てにならないため。

Distribution

会社の PC に持ち込むこと

Tauri はフロントエンドを exe に埋め込むので、PomoSingle.exe 1 つをコピーすれば動く。 インストール不要・管理者権限不要で、実体は約 10 MB。WebView2 ランタイムは Windows 11 に標準搭載されている。 ユーザー領域にインストールする NSIS インストーラも同時に出力される。

未署名 exe は環境に依存する

自前ビルドは署名されていないため、初回実行時に SmartScreen の警告が出る。 組織のポリシー(AppLocker / WDAC / EDR)によっては実行自体がブロックされる。 これはスタックの選択とは無関係に発生するので、配布形態を確定させる前に実機で 1 度試しておくのが確実。
